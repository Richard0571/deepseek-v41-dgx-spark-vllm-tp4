# 11 · 测量纪律

**这篇讲什么**：在这套系统上量出来的数字，什么情况下可以互相比较、什么情况下不能，以及一个数字要怎么写才算「可被第三方复核」。**这一节是通用工程纪律，与具体模型无关。**

---

## 1. 先给数字标来源等级

任何数字（容量、内存、带宽、token 数、时长、价格、比例、并发、耗时、体积）在写进任何地方之前，
先确定它的来源等级：

| 等级 | 含义 | 要求 |
|---|---|---|
| **A** | **量出来的**（本机/本集群实测） | 必须能指出**哪条命令 / 哪行日志** |
| **B** | **别人测的** | 标来源 + 日期 + **「未自测」** |
| **C** | **算出来的** | 必须写出**算式与全部输入** |
| **D** | **未核验** | **不得作为结论依据**，只能写「未核验」 |

### 禁令

- ❌ **禁止**把 C 级推算当 A 级事实输出。
  实录：把「分摊后每 rank 驻留量 ≈ 128 GB」当成「加载要读 128 GB/台」输出，
  而日志实测 loader 逐片迭代了**全部 48 片**、单节点检查点 **475.25 GiB** —— 真值约为该说法的 **3.7 倍**。
- ❌ **禁止**沿用旧文档 / 旧会话里未经复核的数字，**尤其跨会话、跨人接手时**。
- ❌ **禁止**用「听起来合理」替代来源。**「据我所知」「一般来说」「估算约」后面直接给数 = 违规。**
- ❌ **禁止**数字被质疑时去辩解，而不是**当场重新量**。

### 被质疑即重量

**正确反应是立刻去测并给出原始输出**，不是解释原数字为什么合理。

---

## 2. ⭐ 跨 boot 不可直比

**这是本指南最重要的一条测量纪律。**

| 事实 | 实测 |
|---|---|
| 同配置、**不同 boot** 之间的 prefill 差异 | **1.25–1.41×** |
| 同一条 300K prompt，跨 boot | 差 **1.41×** |

⇒ **跨 boot 的数字只能看数量级，不能直比。**

### 怎么保证「同 boot」

```bash
docker inspect <容器名> --format '{{.State.StartedAt}} restarts={{.RestartCount}}'
```

**任何「改动前 / 改动后」的对照，两个读数的 `StartedAt` 必须完全相同。**
把这一行写进每一份测量记录的**头部**。

⚠️ 还有一个坑：某一轮 boot 可能**没有做长预热**。同一套参数、带预热与不带预热的 boot，
长 prefill 的读数不可比（这属于「处理不同」，不是「配置不同」）。
⇒ 若要 A/B 两个配置，用**交替设计**（A/B/A/B），让 boot 级效应在两臂间对称抵消。

## 3. 丢冷样本、重复、报中位 / max / min

| 规则 | 依据 |
|---|---|
| **先丢一个冷样本** | 单点 prefill 首样本可差 **1.63×** |
| **每档 `--repeats 3 --warmup 1`** | 同 boot、同配置、同题 n=3 的极差仍可达 **12.9%（C1）/ 20.8%（C6）**，单格到 **32.7%** |
| **报中位 / max / min** | 只报中位会掩盖单类别异常值 |
| **不要单样本下结论** | 实测过一次 n=3 复测把「档位低 ⇒ 新后缀短」这个单样本结论**完全否证**（同档位方差 **2.4×**） |

**如果两个统计口径（如「对全部值取中位」vs「先分组取中位再取中位」）给出相反的符号，
必须两个都披露**，并明确写「方向不可信」。实测发生过一次：同一条数据在两种口径下配对符号翻转。

---

## 4. 口径必须写清：`agg` 含 TTFT

| 口径 | 定义 | 用途 |
|---|---|---|
| `agg_tok_s` | 总 completion tokens ÷ 墙钟（**墙钟含 TTFT / prefill**） | 端到端体验；**不可对外对比** |
| `decode_agg_tok_s` | Σ completion ÷ (墙钟 − min TTFT) | **对外对比用这个** |

实测差距：`agg` 比 `decode-agg` **低 4.9%（C6）到 12.3%（C1）**。

⇒ **对外报数一律用 decode 口径；两个口径都报并标清。**

### 其它必须写清的口径

| 项 | 要点 |
|---|---|
| prefill 档位 | 写**实测 prompt tokens**，不要写标称档位（历史上有 1.465× 的换算误差） |
| 并发 | 写清 `--max-num-seqs` 与并发数 |
| 上下文长度 | 写清是 prompt 上限还是 prompt+输出之和 |
| 缓存命中 | 三个数摊开：**全量 prompt \| cached \| 未缓存**。别把「未缓存量」当全量 |
| 驱逐 | 「命中/未命中」要区分「条目被驱逐」与「前缀变了」 |

---

## 5. ⚠️ `MemAvailable` 不能用单点读数

单点读数会被**锯齿**误导。实测记录过一串相邻读数：
1,042 / 1,043 / 1,044 / 1,045 / 1,075 / 1,081 / 1,086 / 1,092 MB —— 看起来「一直在危险区」，
但它是**回收与分配交替**的锯齿。

**判据：看连续采样的最低值**（例如 3 秒采样一次，取整个窗口的最小值）。

同理：

- 判「余量」看**最低值**，不是平均值、不是单点；
- 判「有没有触发哨兵」看**增量**，不是累计总数；
- 判「热降频」看**差分的增量**，不是单次累计计数。

---

## 6. 排除「读放大」再谈「内存泄漏」

见 [`docs/07`](07-memory-safety.md) §5。一句话：

**判「内存泄漏」前，必须先排除读放大。**
判据是 `anon` 平（= 页缓存）还是 `anon` 单调涨（= 真泄漏），
以及清掉可疑进程后是否**立刻恢复 GB 级**。

> 历史上有过一条基于读放大得出的结论（「某池每分钟涨 200+ MB」），**已被实测推翻**。

---

## 7. 下否定结论前，先回答「我验证了哪条路径」

写「不成立 / 没有 / 做不到 / 是安全的」之前，必须能回答：

| 问题 | 要求 |
|---|---|
| 我验证了哪条路径？ | 不能只读一个文件就下断言 |
| 我查了哪些调用者？ | 有的接线在**调用者侧**，只读被调用脚本会误判 |
| 我验证了输入分布吗？ | 核验「空值 / 异常值」路径时，必须验证上游是否真的会产生空值（否则你看到的分支可能是**死代码**） |
| 关键步骤**真的生效**了吗？ | 读返回码 + 读日志，不要假设 |

### 两个真实教训

1. **只看空值分支 → 判错**：某脚本里有一个「参数为空则重置」的分支，被断言为 fail-safe。
   实际上游用一个 `awk` 表达式求和，**空输入时仍打印 `0`** ⇒ 那个分支是**死代码** ⇒
   「服务不可达」会被当成「0 个请求」，静默照常累计。**核验空值路径必须验证输入分布。**
2. **只看单个文件 → 判错**：读了清场脚本发现它不停止某类后台进程，就断言「清场后会误杀下一个容器」。
   实际接线在**调用者侧**。**核验「有没有接线」必须查调用者。**

### 结论要写「成立窗口」

一个结论**不能**从前一个时段推广到「历来」。
实测有一次把「某现象解释了历来记录」写进文档，逐条复核后发现：17 条历史记录里 **9 条明确判否**、
**只有 1 条成立**。

⇒ **推广到别的时段/别的配置前，必须逐条核。** 数字标 A/B/C/D；被否定就照实写「已推翻」。

## 8. 实验设计：先预登记判据，再做

在跑之前先写下**判定规则**，避免事后找理由：

```
1. 若两臂差异 < boot 间极差 ⇒ 判「分不出」，并估算「要多少 boot 才能分辨」；
2. 若差异稳定同向且超出极差 ⇒ 判定并给效应量。
```

### 还要先回答一个问题

**「这个旋钮真的接在待测那条链路上吗？」**

实测教训：为一个假设设计了多档阶梯实验（每档含加载 + 长上下文预热，**单档约 40 分钟**），
结果发现**那个参数在本配置下是空转的**（被另一个参数旁路）——
实测「拧到底」与「不拧」的结果**一字不差**。⇒ **那一档实验结构上不可能证伪假设，等于白跑。**

**正确做法**：

1. 查该参数是否被别的参数旁路（读源码取值分支 + 读起服日志的实际取值，两处互证）；
2. 做一次**「旋钮拧到底」的廉价探针**，先证明它有响应，再排阶梯；
3. 写清假设的**证伪条件**，并确认实验设计在该维度上真能产生变化。

### 改完大文件必对 diff

用批量/切片写法改大文件时，很容易写坏（实测：想插 1 行，结果顶部重复了 5 行）。
⇒ 改完做 `diff --stat` 核对增删行数，并检查关键小节计数未变。坏了立刻从备份恢复重做。

## 9. 测量的记录模板

```markdown
## <测量名>
- **boot 身份**：StartedAt=<...>  restarts=<n>     ← 同 boot 对照的前提
- **配置**：GMU=<...> / KVB=<...> / MAXB=<...> / 其它
- **口径**：<agg 还是 decode-agg；并发数；prompt 是实测还是标称>
- **样本**：`--repeats N --warmup M`，已丢弃 <i> 个冷样本
- **结果**：中位 <...>，max <...>，min <...>，逐 rep：<...>
- **余量**：连续采样最低 <...> MB（窗口 <起>-<止>，采样点数 <n>）
- **击杀**：本 boot 增量 = <k>（用 `!! 触发：` 前缀计数）
- **来源等级**：A / B / C / D（逐项标）
- **未核验项**：<...>
```

## 10. 测量纪律检查清单

- [ ] 每个数字都标了 A / B / C / D
- [ ] A 级数字能指出具体命令或日志行
- [ ] 跨 boot 的数字**没有**被直接对比（或已明确标注「只看数量级」）
- [ ] 对照的两个读数 `StartedAt` **完全相同**
- [ ] 已丢弃冷样本；`--repeats ≥ 3`；报了中位 / max / min
- [ ] 对外报数用 **decode 口径**，且两个口径都披露
- [ ] 余量用的是**连续采样最低值**
- [ ] 击杀用的是**增量**，且用正确的 grep 前缀
- [ ] 判「泄漏」前已排除读放大
- [ ] 下否定结论前已核**调用者**与**输入分布**
- [ ] 结论写清了「成立窗口」，没有跨时段过度推广
- [ ] 未核验的写「未核验」，没有用「听起来合理」替代来源

## 0 · 未打 Engram 补丁仍起 TP4（2026-09-14 wedge）

**现象**：spark-03 在权重加载期 wedge —— ping 通、TCP 22 接受、**SSH banner 永不完成**。约 7 分钟后 watchdog reset，未需物理断电。

**根因**：每 rank `475.25 GiB ÷ 4 = 118.81 GiB`（C），大于每台可用约 **114 GiB**。仍起服并指望 `docker --memory 112g` 兜底 —— **GB10 统一内存上 nvidia 驱动代持页不计入 cgroup，cap 拦不住**。

**修法**：

1. `DSV41_ENGRAM_DISK=1` + 七个补丁四台齐（本仓库 `patch/`）。
2. 算出装不下就**不要起**。
3. 起服脚本 `[0/4] guard check`：哨兵不在岗 `exit 3`。

**教训**：哨兵按 ABS 1024 开火追不上 reclaim thrash；正确修法是砍内存需求（Engram-on-disk），不是放宽阈值。

## 0b · 补丁必须四台都有

只 scp 到 head ⇒ worker `docker run` 时 `-v` 源不存在，docker 创建空目录 ⇒ 服务缺 rank。

**修法**：`patch/` 拷到四台同一路径（如 `/home/cq/v41patch/`）。

## 1 · 预检清单把 manifest 自己钉了 md5

**现象**：往 `mounts.txt` 加了一行补丁 ⇒ 预检报

```
FAIL <head ip> patch md5 7/8 (expect 8/8)
=== FAIL — do NOT launch
```

只有 head 失配，三台 worker 是 `8/8`。而且此时**服务已经被清场**（`docker rm -f` 已执行）⇒ **服务中断且不自动恢复**。

**根因**：预检的 md5 清单 = 7 个补丁文件 **+ `mounts.txt` 自己**。
清单里钉的是「7 行版」的 md5；你加了第 8 行 ⇒ 它必然失配。
**新增的那个补丁文件根本没被校验**（它不在清单里）—— 失配的是**清单自己**。

**为什么是结构性耦合**：预检读 `mounts.txt` 校验 md5，起服脚本读**同一个** `mounts.txt` 生成挂载
⇒ 「加补丁」与「过门闸」互斥，除非更新清单。

**修法**（推荐）：把清单里 `mounts.txt` 那条的期望 md5 改成新值，同时更新补丁目录的 README 表。
**更好的修法**：把 `mounts.txt` 从清单里删掉，改为「校验第 1 列列出的文件是否存在且 md5 正确」，
让清单不再自指。

**教训**：**加了清单里的项，就要同步清单的校验值。** 单测这件事的办法是：
改完先 `--dry-run`，再看预检是不是会拦。

## 2 · ⛔ 多行续行里插注释（一行注释废掉整条命令）

**现象**：起服报

```
docker: 'docker run' requires at least 1 argument
bash: 行 9: -e: 未找到命令
```

两个看起来毫不相干的错。

**根因**：`docker run ... \` 这类**续行结构**里插了一行 `# 说明`：

```bash
docker run -d --name X \
  --network host \
# 这里插了一行注释          ← ❌ 致命
  -e FOO=bar \
  bash /entrypoint.sh
```

`\` + 换行会把下一行拼上来 ⇒ `#` 在那一行**开启注释**，把**本行的续行符也吃掉** ⇒ **续行链断裂**：
命令在 `--network host` 就结束了（没有镜像），后面的 `-e ...` 变成一条**独立的新命令**。

这正好解释上面两个错：① 命令缺镜像；② `-e` 被当成命令名。

**为什么特别危险**：`bash -n` **抓不到它** —— 语法完全合法。

**修法**：
- 续行结构里**绝不**插注释（要注释就放在整条命令**之前或之后**）；
- 改完**必须**跑 `--dry-run`，并且**看生成结果而不是脚本本身** ——
  确认镜像行、`-e` 行、`$(...)` 展开都在位。

**代价实录**：因为这个断裂，四台缺一个 rank ⇒ 起服 `NOT READY` ⇒ **服务中断约 25 分钟**。

## 3 · `--dry-run` 会打印明文密钥

**现象**：如果起服命令的续行里用了 `-e KEY="$(cat <密钥文件>)"`，
`--dry-run` 的输出会带**明文**。

**规矩**：
- **不要把 dry-run 输出落盘、转发、贴到任何地方**；
- 更根本的办法：**凭据不要进 argv**。用「从只读文件读」或平台自带的凭据机制，
  而不是把值展开到命令行里。

**顺带一条**：容器参数里带密钥时，`docker inspect` 会**明文列出**它。这是 `-e` 注入的固有属性，
不是某个脚本的 bug。若要看容器参数做排障，**先把这类字段遮掉再分享**。

**另一条**：引擎日志会回显完整的服务端参数（含 key）。**不要把引擎日志全文贴到聊天/工单/仓库。**

## 4 · 提权步骤静默失败（「写了」不等于「生效了」）

**现象**：脚本里有一段「清页缓存」的提权动作，日志只留一行 `xxx GiB available`，
看起来做了，**实际从未执行**。

**根因**：运行账户**没有免密提权**，那条命令报 `需要口令`；
而脚本写了 `> /dev/null 2>&1`，把错误吞掉，然后**继续往下走**。

**判据**：**读返回码 + 读日志**。不要因为「脚本里写了」就当它生效。

**修法**：
- 提权动作改走一个**显式的提权通道**（例如读取一个只读凭据文件，或配一条**最小范围**的免密规则：
  只允许这一条命令，不是「全部免密」）；
- **失败必须回非零并把原文打到 stderr**，不要吞。

**影响**：这条历史上还导致过一个**错误的归因** ——
文档曾把「KV 可复现性」归功于这个动作，而它在自动化路径上从未生效。
⇒ **归因必须建立在「确认生效」之上。**

## 5 · 统一内存的 wedge

**现象**：

| 项 | 状态 |
|---|---|
| `ping` | ✅ 通 |
| TCP `:22` | ✅ 接受 |
| **SSH banner** | ❌ **超时** |
| HTTP 服务 | ❌ 无响应 |
| OOM killer | ❌ 没有记录 |

**根因**：统一内存被推到触顶，内核进入 **reclaim thrash** —— 回收速率赶不上分配速率，
连 `sshd` 都拿不到足够内存完成握手。**这不是干净的 OOM。**

**为什么后果重**：本硬件**没有 BMC / IPMI** ⇒ 只能**物理断电**。

**防它靠什么**（不是靠「少用内存」）：
1. 内核护栏留出回收余量（[`docs/02`](02-host-preparation.md) §2）；
2. **宿主侧哨兵**在触顶前主动杀容器（[`docs/02`](02-host-preparation.md) §3）；
3. 用**容量旋钮**把平台余量本身调厚（[`docs/06`](06-launch-parameters.md) §3）。

**⛔ 出事时不要做的事**：不要轮询 SSH。对已 wedge 的节点反复连接会堆起几百个会话，**拖慢恢复**。
等 25–40 分钟看自愈；不自愈就报给能断电的人。

## 6 · 哨兵阈值照抄 ⇒ 秒级误杀

**现象**：把绝对下限照抄成 **8192 MB**（「留 8 GB 才安全」的直觉）⇒ 容器**几秒内被杀**。

**根因**：本配置**稳态正常运行时** head 的 `MemAvailable` 就只有 **1.6–5 GiB**（实测 1.58–4.8 GiB）。
8 GB 的门槛**在任何时刻都满足**触发条件。

**修法**：绝对下限 = **1024 MB**，**不得放宽 / 停用 / 修改**。

**教训**：**「想更安全」≠「把阈值调高」。** 阈值要贴着**真实危险边界**定，
而不是贴着一个想象中的「安全余量」。定阈值的正确输入是**实测的水位分布**，不是直觉。

## 7 · 大文件走计量代理

**现象**：某个月外网流量异常，一查是一个大模型权重走了代理出口。

**规矩**：**禁止**用计量代理 / 订阅节点下载**单次任务总量 > 5 GB** 的内容（按总量算，不按单文件）。

**判据（很有迷惑性）**：**环境变量为空 ≠ 没走代理。**
系统级（注册表 / 图形设置）的代理可能对某些 HTTP 客户端**自动生效**。

最强的信号是**不对称**：同一个 URL、同一时刻，A 客户端全失败而 B 客户端高速成功
⇒ **唯一现实解释是其中一个读了系统代理**。
**不要读成「A 工具有 bug、B 工具更快」** —— 那是把路由问题误判成工具问题。

**修法**：
1. 先测这次下载走不走代理（**环境变量 + 系统级设置**都要查）；
2. 走代理就换路（局域网 / 明确绕过的直连 / 镜像源）；
3. 换不了就**停下来问**；
4. **下载完记一笔**（内容 + 大小 + 走的哪条路）。

## 8 · 在模型目录上递归扫描（会伪装成内存泄漏）

**现象**：内存监控出现持续「漂移」，看起来像泄漏。

**根因**：一条诊断命令在放着几百 GB 模型的目录上做了递归 `grep`。
因为结尾的 `| head -30` 没凑够 30 个命中，`grep` **不提前退出**，把整棵树读完了 ——
实测读了 **2.888 TB**、跑了 **58 分钟**、速率约 **840 MB/s**，
把页缓存反复灌满/回收，**伪造出「内存持续漂移」**。

**判据**：

| 特征 | 读放大 | 真泄漏 |
|---|---|---|
| `anon` | **平** | **单调涨** |
| `cached` | 大幅摆动 | 缓慢变 |
| 磁盘 `read_bytes` 增速 | **几百 MB/s** | 低 |
| 清掉进程 | **立刻恢复（GB 级）** | 不恢复 |

清掉后即时恢复：`MemAvailable` 3,024 → **6,515 MB**。

**修法**：只搜**具体文件或明确的小目录**；要全树搜就先 `--exclude-dir` 掉权重目录。
**长命令不要 `| head -N` 之后就丢下不管** —— 跑之前先想「它要读多少」，跑完确认进程真的没了。

## 9 · 性能对照的陷阱

| 陷阱 | 实测证据 | 处置 |
|---|---|---|
| **跨 boot 直比** | 同配置跨 boot prefill 差 **1.25–1.41×** | 跨 boot 只看数量级，不能直比 |
| **单点采样当余量** | 单点 `MemAvailable` 会被锯齿误导（一串 1,042–1,092 MB） | 看**连续采样的最低值** |
| **单点首样本当性能** | 单点 prefill 首样本可差 **1.63×** | **先丢一个冷样本** |
| **单样本当结论** | 同 boot 同题 n=3，档位间无单调关系，同档位方差 **2.4×** | `--repeats 3 --warmup 1`，报**中位 / max / min** |
| **口径混用** | `agg_tok_s` 含 TTFT，比 decode 口径低 5–12% | **对外一律用 decode 口径**，两个口径都要标 |
| **旋钮没接线就去做 A/B** | GMU 对 KV **完全无影响**（0.80→0.78，KV 一字不差） | 花机时前先做「旋钮拧到底」的廉价探针 |

**一句话**：**先证明实验设计在该维度上真能产生变化，再排阶梯。**
否则那一档实验**结构上不可能证伪假设，等于白跑**。

详见 [`docs/11`](11-measurement-notes.md)。

## 10 · 加了补丁、容器也重建了，但补丁没生效

**四种可能，按概率排序**：

| # | 原因 | 判据 |
|---|---|---|
| 1 | **根本没挂上**（files 或清单没同步，或手工 `docker run`） | 容器内目标不是普通文件；或 `docker inspect .Mounts` 里对应项缺失 |
| 2 | **挂上了但文件不对**（源路径写错 ⇒ docker 创建空目录） | 容器内目标是**目录**（`stat -c %F`） |
| 3 | **挂上了、文件对，但代码缺 `import`** | `/health` **200**，但每个请求 500 |
| 4 | 挂上了，但**另一个同名文件先被加载** | 需要看 traceback 的路径 |

**铁律**：**容器重建 ≠ 补丁生效。** 必须做两件事：

1. **核 host 与容器内 sha256 一致**；
2. **发一个最小请求**（`/health` 200 **不代表**代码没错）。

## 附加坑（同族，一并记下）

| 坑 | 现象 | 处置 |
|---|---|---|
| **PowerShell → ssh 的引号剥离** | `ssh host 'printf "A B\n" >> f'` 经 PowerShell 传参时内层双引号被剥掉 ⇒ `printf` 把首词当格式 ⇒ **只写入 `A`、无换行**，文件看起来「加了一行」实际是半行 | 经 PowerShell 下发到远端的命令**不要放双引号**；追加整行用 `echo a b >> f` |
| **CRLF 污染** | 参数读成 `0.80\r`；脚本报 `set: pipefail: 无效的选项名` | 推文件前后核 `CR = 0`；`.env` 类文件同样适用 |
| **后台进程被 SSH 断开带走** | 普通 `nohup ... &` 在 SSH 断开后被杀 | 用 `setsid nohup ... &` |
| **击杀计数读错** | `grep -c 触发` 把分隔行/水位行都算进去（实测 6 行 ≠ 2 次） | 用 `grep -c '!! 触发：'` |
| **哨兵重启清空日志** | 刚发生的击杀证据被抹掉 | 改 append + 轮转，不要 `> "$LOG"` |
| **GPU 时钟 latch（慢态）** | 一切正常跑，但所有性能数字被静默污染（频率 700–950 MHz） | 起服前的 burn 门禁（[`docs/05`](05-preflight.md) §4） |
| **把残差当直测量** | 把「总内存 − 已列举项」这个**残差**命名为某个具体池并据此下结论 | 残差 = 残差；要结论就做专测 |
| **把「能 import」当「能跑」** | 曾经两次致命崩溃都发生在 import 全绿之后 | 起服后**必须**发最小请求 + 长 prefill 正确性检查 |
| **前缀缓存被当成「必然命中」** | 「前缀没变 ⇒ 缓存必中」不成立；同一 prompt 连发 3 次可全 0 | 见 [`docs/12`](12-engine-runtime-notes.md) |
| **带 tools 的历史思考被强制保留** | 每步停顿数秒，且调「思考档位」无效 | 见 [`docs/12`](12-engine-runtime-notes.md) |

## 排障记录应该写什么

发现问题时，按这个格式记一笔（写进你项目的排障账）：

1. **现象**（原始报错 / 读数）
2. **根因**（已知就写，未知写「未核验」）
3. **是否已修**
4. **待确认项**

**别写「可能是 X」当结论。** 未核验的写成「未核验」，与后续协作者才有价值。
